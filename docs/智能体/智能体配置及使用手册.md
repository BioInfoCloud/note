### 写在前面

#### 这份手册解决什么问题

很多人第一次接触 AI 智能体时，卡住的地方并不是"不会用"，而是"装不起来"。命令行窗口里一串红色报错、API 密钥不知道去哪里申请、选好了模型却不知道填什么接口地址，这些琐碎但致命的环节，把大量初学者挡在了门外。

本手册不讨论算法原理，也不评价某款模型"好不好"，它只回答一件事：**如何把一套能真正干活的智能体环境，从零开始在自己的电脑上搭起来，并稳定运行下去。**

手册覆盖的完整路径是：

1. 理解大模型的工作原理、固有缺陷与补救办法，知道自己在跟什么样的东西打交道；
2. 理解智能体的基本构成，知道自己在配置什么东西；
3. 了解可用的大模型与评测榜单，能独立选型；
4. 装好运行环境，拿到可用的 API 密钥；
5. 安装并配置五款主流智能体产品；
6. 用 CC Switch 做模型路由，让原本绑定国外模型的产品也能用上国内模型。

走完这六步，你将拥有一套"模型可换、工具可扩展、成本可控"的个人智能体工作环境。

### 第 1 章　大模型是怎么工作的

#### 1.1 一切从"预测下一个字"开始

大语言模型做的事情，说穿了只有一件：**根据已经出现的文字，预测下一个最应该出现的字**。你给它"今天天气很"，它算出接下来最有可能是"好"；你把答案接回原文，再让它预测下一个，如此循环往复，一句话、一段话、一篇文章就这样被"接龙"出来。

这件看似简单的事，在足够大的规模上产生了质变。当模型读过近乎互联网上所有的公开文本，并且参数量达到百亿、千亿级别时，它在这个过程中不得不学会语法、事实、逻辑乃至某种程度的推理，否则就无法准确完成预测任务。这些能力不是被显式教出来的，而是被预测任务"逼"出来的副产品。

训练大致分三个阶段：

| 阶段 | 名称 | 做什么 | 解决什么问题 |
| --- | --- | --- | --- |
| 第一阶段 | 预训练 | 在海量文本上反复练习"预测下一个字" | 获得语言能力、世界知识与基本推理能力 |
| 第二阶段 | 监督微调 | 用人工编写的高质量问答对进一步训练 | 学会理解指令，能按人类期望的方式回答 |
| 第三阶段 | 偏好对齐 | 根据人类对多个答案的偏好打分来调优 | 让回答更安全、更有用、更符合人类习惯 |

> **提示**：理解"预测下一个字"这一点，是理解后面所有现象的关键。无论是模型的聪明、它的偏见，还是它的胡编乱造，都能从这一个机制推导出来。

#### 1.2 三个必须知道的基本概念

**参数**：模型内部用来存储"知识"的可调节数值，可以理解为它从训练数据里压缩出来的记忆。常说的"7B"，"671B"指的就是参数量，1B 等于 10 亿。参数量大体决定了模型的能力上限，也决定了运行它需要的硬件资源。对个人用户而言，参数量不用记，只要知道它对应模型的"档次"即可。

**Token**：Token 是大模型处理文本的基本单位，也是计费单位。**中文大约 2 个字折合 1 个 Token，英文常把一个长单词拆成多个 Token**。我们常看到的 “支持 128K 上下文”“每百万 Token 多少钱”，这里的单位都是 Token。

**上下文窗口**：模型一次能同时"看到"的文字总量上限，包含你输入的内容、历史对话以及它自己的输出。超出这个上限的部分会被丢弃或压缩，这就是为什么长对话进行到后面，模型会忘记开头说过的话。

| 概念 | 一句话解释 | 与你有关的地方 |
| --- | --- | --- |
| 参数 | 模型的知识容量 | 决定能力上限与运行成本 |
| Token | 文本的最小计量单位 | 决定你的花费，也决定上下文能装多少 |
| 上下文窗口 | 一次对话的容量上限 | 决定任务能有多长，超出就会遗忘 |
| 知识截止日期 | 训练数据覆盖到的时间 | 此后的事情模型不知道，需要联网或检索 |

> **注意**：模型并不"知道"今天几号，也不"知道"自己的知识截止到什么时候。它对时间没有内在感知，只是训练数据里包含某个时间点之前的信息。问它截止日期之后发生的事，它往往会用旧信息拼出一个看似合理的答案，这正是下一章要讲的幻觉。

#### 1.3 大模型擅长什么，不擅长什么

把能力边界说清楚，比罗列能力更重要。

| 维度 | 擅长的 | 不擅长的 |
| --- | --- | --- |
| 语言 | 改写、润色、摘要、翻译、格式转换 | 需要绝对精确的文字，如法律条文的逐字引用 |
| 知识 | 通识性、高频出现的知识 | 长尾、冷门、时效性强的信息 |
| 推理 | 常规逻辑推演、多步骤分析、思路梳理 | 精确数值计算、严格的符号推导 |
| 创造 | 提供思路、生成草稿、启发联想 | 替代专业判断与审美决策 |
| 信息 | 已知信息的组织与重组 | 未知信息的获取，尤其是实时信息与私有数据 |

> **提示**：一个实用的判断标准是，凡是"能靠语言规律推出来"的事，模型都做得不错；凡是"必须查证才能知道"的事，模型都不该被单独信任。写代码属于前者居多，查文献属于后者居多。

#### 1.4 由此推出的四条使用原则

**第一，把它当助手，不要当权威。** 模型的输出是高质量的初稿，不是结论。它能帮你从一片空白迅速做到六七十分的水平，剩下的部分需要你的专业判断来补。

**第二，任务拆细，一次一事。** 把一个大问题拆成若干个明确的小步骤，每一步单独确认，质量远高于一次性扔给它一个笼统的要求。

**第三，给出上下文和约束。** 说明你的身份、目标、受众、格式要求、篇幅限制、哪些内容不要出现。信息给得越充分，输出越接近预期。

**第四，让它说明依据。** 要求模型在给出结论时一并说明推理过程与信息来源，并明确允许它回答"我不知道"。这一条能显著减少下一章要讲的幻觉。

### 第 2 章　幻觉：模型为什么会一本正经地编造

#### 2.1 什么是幻觉

幻觉（Hallucination）指的是模型生成了**与事实不符、但表述流畅且语气自信**的内容。它的危险之处不在于"错"，而在于"错得很像真的"：格式规范、逻辑自洽、细节完整，读起来毫无破绽，让人本能地放松警惕。

在科研与教学场景中，幻觉的代价尤其高昂。一条虚构的参考文献、一个编造的统计数字、一个张冠李戴的实验方法，一旦进入论文或课件，纠正成本远高于当初核验的成本。

#### 2.2 幻觉从何而来

| 成因 | 机制 | 典型表现 |
| --- | --- | --- |
| 训练数据含噪声 | 互联网文本本身就有大量错误、过时与相互矛盾的内容 | 复述流传较广的错误说法 |
| 概率生成本质 | 模型优化的目标是"流畅合理"，而不是"事实正确" | 把最像答案的内容说成答案 |
| 知识的有损压缩 | 千亿参数无法完整记住海量事实，长尾信息丢失或串接 | 冷门事实错误，细节张冠李戴 |
| 缺乏外部知识源 | 模型生成时不查资料，只能依赖内部记忆 | 对知识截止后的事件凭空推测 |
| 提示词诱导 | 引导性提问，或要求"必须给出答案" | 为迎合提问而编造 |
| 采样随机性 | 温度较高时，低概率但更"有创意"的选项被选中 | 天马行空，偏离事实 |

> **提示**：最关键的一点是，流畅性与正确性在模型内部是两件独立的事。它说话顺溜，只说明它掌握了语言规律，完全不能证明它掌握了事实。

#### 2.3 三种最常见的表现

**编造文献与引用。** 这是科研工作中最需要警惕的一类。模型可能生成看起来完全规范的参考文献，包含作者、期刊、年份、卷期页码甚至 DOI，但这篇文章并不存在。另一种情况是文章真实存在，但作者、结论或期刊被张冠李戴。

**虚构数字与事实。** 编造统计数据、实验参数、药物剂量、基因编号、政策条文的具体内容与生效时间。数字类幻觉尤其隐蔽，因为它往往与其他真实数字混在一起。

**混淆与越界推断。** 把 A 研究的方法说成 B 研究的结论，把动物实验的结果说成临床结论，把相关性表述为因果性。这类错误不一定是完全虚构，而是对真实信息的错误组合。

#### 2.4 五个识别信号

1. **具体而不可核验**：给出了非常具体的细节，但按图索骥却查不到出处；
2. **语气过度确定**：对理应存在争议或需要限定条件的问题给出斩钉截铁的回答；
3. **细节自相矛盾**：同一段回答中前后数字、时间、名称不一致；
4. **追问即改口**：追问依据时，它承认"我无法确认"或换一个说法；
5. **换个问法答案就变**：同一问题重新提问，得到的答案实质性不同。

> **提示**：一个低成本的验证技巧是"换窗口重问"。新开一个对话，把问题重新表述一遍，如果两次答案在关键事实上不一致，那么至少有一个是编的。

#### 2.5 六条应对策略

| 策略 | 具体做法 |
| --- | --- |
| 要求提供依据 | 明确要求给出信息来源、推理过程，并允许回答"不确定" |
| 限定回答范围 | 限定只依据给定材料作答，材料中没有就直说没有 |
| 关键信息交叉验证 | 文献查数据库，数字查原始来源，法规查官方文本 |
| 降低温度 | 事实性任务把温度调到 0 或接近 0，减少随机性 |
| 引入外部知识 | 用第 3 章的 RAG 把真实资料接入，让模型看着材料回答 |
| 建立复核习惯 | 凡是要写进论文、课件、报告的内容，逐条人工核对 |

#### 2.6 科研与教学场景的特别提醒

- **文献引用一律核验**。凡模型给出的参考文献，都要在 Web of Science、PubMed、Google Scholar 或期刊官网检索确认，重点核对 DOI 与作者。
- **实验参数不得直接采信**。剂量、浓度、温度、时间、序列、引物等关键参数，必须回到原始文献或实验记录核对。
- **专业名词重点检查**。基因名、蛋白名、通路名、药物名、疾病编码这类术语，是幻觉的高发区，也是最容易被同行一眼看穿的地方。
- **统计结论需复核**。样本量、P 值、置信区间、效应量等数字，用原始数据重算一遍再引用。
- **教学材料提前试做**。课件中的示例、代码、数据如果来自模型生成，上课前务必自己跑一遍。

> **注意**：不要让模型成为你了解一个陌生领域的唯一信息源。用它来建立初步框架、梳理思路、提出该查什么，然后用真实文献把框架填实。顺序反了，就会把幻觉当成知识沉淀下来。

### 第 3 章　RAG：给模型外挂一个资料库

#### 3.1 它解决什么问题

第 2 章讲到的幻觉，有相当一部分源于同一个困境：模型只能依靠训练时记住的东西作答，既看不到你的私有资料，也看不到知识截止之后的新信息。

RAG（Retrieval-Augmented Generation，检索增强生成）给出的解法很朴素：**先去资料库里把相关内容找出来，把找到的内容连同问题一起交给模型，让它看着材料回答。**

这样一来，模型不再需要凭记忆作答，而是变成了"阅读理解"。它的语言与推理能力照常发挥作用，事实准确性则由你提供的真实资料兜底。

#### 3.2 四步流程

| 步骤 | 名称 | 做什么 | 关键要点 |
| --- | --- | --- | --- |
| 第一步 | 文档准备与切分 | 把资料整理成纯文本，切成一个个语义完整的片段 | 按段落或章节切分，避免把一个完整论述拦腰截断 |
| 第二步 | 向量化与入库 | 用 Embedding 模型把每个片段转成向量，存入向量库 | 中文场景选择中文 Embedding 模型，可参考 MTEB 榜单 |
| 第三步 | 检索 | 把提问同样转成向量，找出语义最相近的若干片段 | 可先粗召回再重排序，兼顾速度与精度 |
| 第四步 | 增强生成 | 把检索到的片段拼进提示词，要求模型依据材料作答并注明出处 | 明确要求"材料中没有就回答不知道" |

> **提示**：RAG 的效果上限由你的资料质量决定，而不是由模型决定。这就是常说的"垃圾进，垃圾出"。整理一份干净、权威、结构清晰的资料库，比换一个更强的模型更有效。

#### 3.3 RAG、微调与长上下文怎么选

三种方案都能让模型"知道更多东西"，但原理与代价完全不同。

| 对比项 | RAG | 微调 | 超长上下文 |
| --- | --- | --- | --- |
| 原理 | 回答时临时检索外部资料 | 用数据继续训练，改变模型自身 | 一次性把全部资料塞进输入 |
| 知识更新 | 改资料库即可，即时生效 | 需要重新训练 | 每次对话重新塞入 |
| 成本 | 低，主要是存储与检索开销 | 高，需要训练资源与数据工程 | 随资料量线性增长，很贵 |
| 可溯源 | 可以，能指出答案出自哪一段 | 不可以 | 勉强可以 |
| 擅长 | 事实问答、资料查询、需要溯源的场合 | 固定风格、特定任务格式、领域术语习惯 | 资料量不大且需要整体理解时 |
| 不擅长 | 让模型学会新的表达风格 | 频繁更新的知识 | 海量资料的日常问答 |

> **提示**：对绝大多数个人与教学场景，RAG 是首选。它便宜、可控、随时可改，而且每一条答案都能追溯到具体的段落，这一点对科研工作尤其重要。

#### 3.4 什么时候该用，什么时候不必用

**适合用 RAG 的情况**：你有一批自己的资料需要反复查询，比如课题组的历史文档、某个方向的文献集合、课程讲义与实验手册；你需要答案能指出处；资料会持续更新；资料总量超出上下文窗口。

**不必用 RAG 的情况**：你只是想让模型帮你改写、润色、梳理思路，这些任务靠模型自身能力就够；资料只有几页，直接粘贴进对话即可；你真正需要的是提升模型的推理或写作风格，那属于微调的范畴。

#### 3.5 落地要点

- **资料先行**。优先收录权威来源，剔除重复、过期与相互矛盾的内容，统一格式后再入库；
- **切分讲语义**。按标题层级或自然段落切分，每个片段保持论点完整，片段之间可保留少量重叠以免切断语义；
- **选对 Embedding 模型**。中文资料务必选用中文能力强的嵌入模型，参考 MTEB 榜单选择；
- **控制检索数量**。通常取 3 到 8 个片段，太少容易漏，太多引入噪声稀释重点；
- **在提示词中设约束**。明确要求只依据材料作答，材料不足时直接说明，并在答案中标注引用编号；
- **建一个小评测集**。准备十几条你确定答案的问题，每次调整配置后跑一遍，用真实通过率判断改进是否有效。

#### 3.6 RAG 的局限

RAG 不是万能药，它有四个绕不开的限制：

1. **检索不到就答不出**。如果资料库里没有，或者检索环节没召回，模型依然只能凭记忆作答，幻觉照旧；
2. **切分会破坏语义**。跨段落的论证、依赖表格的数据，切分后可能丢失关联；
3. **不提升推理能力**。RAG 只解决"知道什么"，不解决"能不能想清楚"，材料再全，推理薄弱的模型依然会得出错误结论；
4. **纯向量检索对精确匹配不敏感**。产品编号、基因符号、精确短语这类需要字面匹配的内容，需要配合关键词检索一起使用。

> **提示**：把 RAG 理解为"给模型配了一个查得到、报得出的资料员"，而不是"给模型做了知识植入手术"。它解决的是信息可及性与可溯源，不解决能力本身。

#### 3.7 与本书后续内容的关系

RAG 并不是一个需要你从头搭建的东西，它已经以各种形态存在于本书后面的内容中。

智能体的 **SKILL** 常常就是把领域资料与操作流程打包在一起的产物；**MCP** 让智能体能够直接查询外部数据库与文件，本质上也是把外部信息接入生成过程；像 BioMed AI 这样的领域集成应用，内置了专业资料库与分析工具，同样属于 RAG 思路的落地形态。

理解了这一层，你在后面配置 SKILL 与插件时，就知道自己真正在做什么：不是在给模型"加知识"，而是在给它接上一条通往真实资料的通道。

### 第 4 章　从大模型到智能体：七个核心概念

#### 4.1 从"会说话"到"会干活"

前面三章讲的是大模型本身。你已经知道它本质上是在预测下一个字，知道它会编造，也知道可以用 RAG 给它接上真实资料。

但仍然有一个问题没有解决：**模型只会说，不会做。**

你问它"帮我整理这个文件夹里的实验记录"，它能告诉你该怎么整理，却无法真的打开文件、读取内容、生成表格。它像一个被关在屋子里、只通过窗口与你交谈的顾问，什么都知道，什么都做不到。

智能体要解决的正是这件事。它在模型外面套上一层"手脚"，让模型能够读写文件、执行命令、调用工具，并且自己规划先做什么后做什么。从模型到智能体，是本章要讲的核心跨越。

这一层跨越带来了一批新概念：智能体、SKILL、Tool、MCP、上下文、温度，再加上前面已经出现过的大模型与提示词，一共七个。下面用一个贯穿全书的比喻把它们串起来。

#### 4.2 一个贯穿全书的比喻

![](https://raw.githubusercontent.com/BioInfoCloud/ImageGo/main/figure20261101133859173.png)

想象你在网上买了一个柜子，需要有人上门帮你装好。整个安装过程里出现的人和物，恰好对应智能体世界的七个基本概念。

**① 大语言模型 LLM —— 师傅的大脑**
能听懂你的要求、看懂图纸、推理和回答问题，但**只输出文字，不会真的执行动作**。它是智能体的"思考核心"，负责理解意图、规划步骤、判断下一步做什么。

**② 智能体 Agent —— 师傅本人 + 手边的工具**
在 LLM 基础上加上"动手"的能力：能自己规划先装底板还是侧板、调用工具一步步执行、中途卡住会翻说明书或换方法重试，直到任务完成。**LLM + 工具调用 + 自主循环 = Agent**，这是它和聊天机器人的本质区别。

**③ Skill 技能包 —— 成套操作手册**
一个包含 `SKILL.md`（外加可选脚本、参考资料）的文件夹，封装的是**流程性知识**：这类任务按什么步骤做、查什么信息、按什么格式输出、边界怎么处理。采用**渐进披露**加载：先只读摘要，命中了才读正文，正文引用时才加载附件，所以几乎不占上下文。可多本组合复用。

**④ Tool 工具 —— 单件实物工具**
最小的、单次调用的能力单元，一次只做一件事：卷尺只测量、螺丝刀只拧螺丝、电钻只打孔。Skill 会去调用工具，但它本身不是工具。

**⑤ MCP（Model Context Protocol）—— 通用工具快接头**
一套开放协议，规定智能体如何标准化接入外部能力，不必为每个工具单独写适配代码。一个 MCP 服务可对外提供三类东西：**tools（工具）、resources（数据）、prompts（提示模板）**​。

**⑥ 上下文 Context —— 师傅脑子里的现场信息**
不只是聊天记录，还包括系统提示、工具返回结果、检索到的外部资料。它是**有容量上限的工作记忆**：装不下就会被截断或压缩总结，这才是长任务后半程"跑偏、忘事"的根因。

**⑦ 温度 Temperature —— 干活的灵活度**
调低：严谨保守，几乎按最可能的答案走，适合写代码、严谨推理；调高：更有创意和发散，也更容易自作主张、出错。不同厂商取值范围不同（常见 0–1 或 0–2），且即使设为 0 也不保证逐字完全一致，严谨场合应说"近似确定性"。

**⑧ 提示词 Prompt —— 你下的需求单**
你交给模型的任务描述与约束。写得越清楚（目标、格式、边界、示例），结果越准；写得模糊，模型就会自由发挥，出现漏项或偏差。

> **提示**：**你写下需求单（Prompt）→ 大脑（LLM）思考怎么干 → 师傅（Agent）开始动手 → 翻操作手册（Skill）查流程 → 拿起单件工具（Tool）→ 通过通用接口（MCP）接上外部系统 → 全程靠现场记忆（Context）记着进度 → 按灵活度（Temperature）决定发挥多少。**

#### 4.3 概念速查表

| 概念 | 比喻 | 核心特征 |
| --- | --- | --- |
| 大语言模型 | 师傅的大脑 | 理解、推理、对话，但不动手 |
| 智能体（Agent） | 师傅本人加上工具箱 | 有目标、能规划、会调用工具、能执行 |
| SKILL | 可外部调取的成套操作手册 | 封装能力、可复用、多手册可组合，不属于大脑内部记忆 |
| Tool（工具） | 螺丝刀、卷尺这类单件工具 | 最小执行单元，单次完成单一动作 |
| MCP | 通用工具快接头协议 | 统一接入标准，让智能体即插即用各类外部工具与资源 |
| 上下文（Context） | 师傅干活记住的全部现场信息 | 保存任务历史、资料、进度，存在记忆上限 |
| 温度（Temperature） | 师傅的发挥灵活度 | 控制模型随机性，低温严谨，高温创意发散 |
| 提示词 | 你给师傅的需求单 | 任务指令，决定干什么、怎么干 |

> **提示**：SKILL 与模型的记忆能力是两回事。模型本身的知识来自训练，是固定的；SKILL 是外部挂载的操作规程，随时可以增删更新。正因为 SKILL 可以外挂，不同人给同一个模型配上不同的 SKILL，就能把它改造成完全不同用途的专用助手，这也是本手册第 6 章与后续各产品章节反复涉及 SKILL 配置的原因。

| 10 | Vidu Skills | AI 视频产品 | <https://www.vidu.cn/> | 生数科技自研 AI 视频生成模型，支持文生视频、图生视频、参考生视频，含 Vidu Agent |

#### 6.3 挑选与安装 SKILL 的三条经验

**先看来源，再看功能。** SKILL 本质上是一段会被智能体执行的指令，来源不明就意味着风险未知。优先选择官方仓库、有明确维护者的开源项目，以及经过安全审核的社区精选。SkillHub 这类平台提供安全审核，相对更适合新手。

**一个项目一个目录。** 建议为每个任务单独建一个工作文件夹，把该项目用到的 SKILL 集中放置。这样做的好处是切换项目时不会互相干扰，也方便把整套配置打包分享给同事。

**先跑小任务验证。** 新装的 SKILL 第一次使用时，先给一个规模很小的任务，确认输出符合预期，再投入正式工作。这一步能提前暴露路径错误、依赖缺失等问题。

> **注意**：SKILL 会被赋予执行操作的权限，安装前请浏览一下它的说明文件，了解它要访问哪些目录、调用哪些工具。不要安装来源不明、说明含糊的技能包。

## 第二部分　环境准备

本部分只有两件事：装好 Node.js，拿到 API 密钥。这两步是所有命令行类智能体的共同前提，做一次即可，后续安装任何产品都建立在这个基础之上。

### 第 7 章　安装 Node.js

#### 7.1 为什么必须先装它

OpenCode、DeepSeek Harness 等智能体产品本身是用 JavaScript 生态开发的，它们的安装与运行依赖 Node.js 提供的运行时环境。这个依赖是隐式的，如果你直接去装智能体，往往会在安装阶段遇到莫名其妙的报错，追查下去才发现是 Node.js 缺失或版本过低。所以请务必提前安装。

#### 7.2 下载与安装

Node.js 官方下载地址：<https://nodejs.org/zh-cn>

进入官网后，页面会自动推荐适合你系统的版本，选择 LTS（长期支持版）下载即可。LTS 版本更新频率低、稳定性好，适合作为日常开发环境。

![](https://raw.githubusercontent.com/BioInfoCloud/ImageGo/main/figure20260921140706050.png)

安装过程一路点"下一步"即可，全部保持默认选项。安装程序会自动配置环境变量，无需手动干预。

> **注意**：如果电脑上此前装过很旧版本的 Node.js，建议先卸载再安装新版本。部分智能体对 Node.js 版本有下限要求，版本过低会导致安装失败。

#### 7.3 验证方法

安装完成后，**务必重新打开一个新的命令行窗口**（已经打开的窗口不会加载新的环境变量），输入以下命令并回车：

```shell
node -v
npm -v
```

两条命令分别会输出 Node.js 与 npm 的版本号，例如 `v22.11.0` 与 `10.9.0`。只要能看到版本号，就说明安装成功。如果提示"不是内部或外部命令"，说明环境变量没有生效，重启一次电脑通常即可解决。

### 第 8 章　API 密钥的获取与安全管理

#### 8.1 什么是 API 密钥，为什么必须有它

大模型服务部署在厂商的服务器上，你的智能体在本地运行，两者之间的每一次对话都要通过网络完成。API 密钥就是你调用这些服务的凭证，相当于一张既证明身份又负责记账的通行证。

没有密钥，智能体就只是一个空壳，能启动但无法思考。有了密钥，你的每一次提问都会被计入账户消费。因此密钥兼具"钥匙"和"银行卡"两重属性，这也决定了它必须被妥善保管。

获取密钥有两条路径：

1. **直接去模型开发商的官网**申请，比如 DeepSeek、智谱 AI、阿里云百炼；
2. **通过第三方聚合平台**申请，一个密钥可以调用多家模型，省去逐个注册的麻烦。

两条路径没有优劣之分，取决于你的使用习惯。如果你只用某一家模型，走官网最直接；如果你想频繁对比不同模型，聚合平台效率更高。

### 第 9 章　五款产品总览与选型

#### 9.1 产品简介

**WorkBuddy（腾讯）**：腾讯云的 AI 桌面工作站与办公智能体，不只做代码。它能理解自然语言、自主规划并执行任务，产出文档、报告、代码等可验证的结果。旗下还有 CodeBuddy Code，一款带 sub-agent、MCP 与 IDE 集成的编码命令行工具。

**OpenCode**：开源编码智能体，终端、IDE、桌面三端可用。通过 Models.dev 接入 75 家以上模型供应商（含本地模型），模型不锁死，具备 LSP 与多会话并行能力（同一个项目可以同时跑多个 agent）。它是产品，不是框架，但提供插件机制。

**Claude Code（Anthropic）**：终端里的交互式编码智能体，主打"人始终在循环里"（in-the-loop）。本地运行，用 `CLAUDE.md` 存放仓库规则，提供 25 个生命周期 hook、sub-agent 与 Agent Teams、MCP，当前在 SWE-Bench Verified 上分数较高。

**OpenAI Codex（CLI）**：OpenAI 的编码智能体，走异步"交接"工作流，默认在云端沙箱运行，使用 `AGENTS.md`（开放标准），支持并行云端沙箱子智能体，单任务 Token 效率更高。

**DeepSeek Harness**：DeepSeek 官方推出的智能体运行框架（Harness），官方公式是 Agent = Model + Harness。模型只是"灵魂"，Harness 提供让智能体在真实环境里干活的一切：文件访问、工具调用、内存、沙箱、重试、任务拆解、结果交付。架构基于 Cordis 微内核，一切皆插件，模型适配器、工具、Skill、会话、存储、agent loop 都是插件。它是"造 Agent 的环境"，不是某一款具体的模型产品。

#### 9.2 选型对照表

| 维度 | DeepSeek Harness | OpenCode | Claude Code | Codex CLI | WorkBuddy（腾讯） |

| 出品方 | DeepSeek | 开源社区 | Anthropic | OpenAI | 腾讯云 |

| 运行形态 | 本地优先，插件化 | 终端、IDE、桌面 | 本地终端 | 默认云端沙箱 | 本地桌面加云 |

#### 11.4 SKILL 的配置

OpenCode 的 SKILL 有两种配置层级，按需选择即可。

##### 全局配置

修改全局配置文件，路径中的 `Lenovo` 是用户名，请替换为你自己的用户名。

```text
C:\Users\Lenovo\.config\opencode\opencode.json
```

打开文件后，把你的 SKILL 所在路径添加到 `paths` 中。下面的示例配置了三个路径。

![](https://raw.githubusercontent.com/BioInfoCloud/ImageGo/main/figure20260921160737501.png)

```json
{

  "skills": {
    "paths": [
      "E:/BaiduSyncdisk/00-gitHubProjects/ai-skills/skills/skills",
      "E:/BaiduSyncdisk/00-gitHubProjects/ai-skills/nature-skills/skills",
      "E:/BaiduSyncdisk/00-gitHubProjects/ai-skills/OpenClaw-Medical-Skills"
    ]
  }
}
```

##### 项目配置

在项目文件夹中创建一个名为 `.opencode/skills` 的两层文件夹，把该项目用到的 SKILL 放进这个文件夹即可。

> **提示**：全局配置适合放通用 SKILL，比如文档处理、代码规范；项目配置适合放专用 SKILL，比如某个课题特有的分析流程。两者可以同时生效，项目级配置的优先级更高。

> **注意**：配置文件中的路径请使用正斜杠 `/`，即使在 Windows 上也是如此。使用反斜杠时需要在 JSON 中转义，容易出错。

## 第四部分　模型路由

### 第 15 章　CC Switch 的安装与配置

#### 15.1 它解决什么问题

Claude Code 与 Codex 这类产品在设计时默认绑定自家模型，想让它们改用国内模型，按常规方式要手工改写一系列环境变量和配置项，过程繁琐且容易出错。

CC Switch 把这件事变成了一个可视化操作：你在界面上填好国内模型的接口信息，它负责把这些配置注入到对应产品中，并可以随时切换回原配置。这就是所谓"路由"。

对国内用户而言，它最大的价值是让原本必须用海外模型的产品也能稳定地跑在国内模型上，既省成本，又免去网络困扰。

#### 15.2 下载及安装

![](https://raw.githubusercontent.com/BioInfoCloud/ImageGo/main/figure20261015161744548.png)

| 模型角色 | 定位与用途 | 推荐填入的模型 ID（硅基流动） |
| --- | --- | --- |
| Sonnet | 默认主力模型，日常编码首选。中等推理能力，速度、成本、代码能力均衡，用来写业务代码、重构、代码审查、调试普通 bug，是 Claude Code 默认使用的角色。 | `deepseek-ai/DeepSeek-V4-Flash` |

| Haiku | 轻量极速模型。适合简单、大批量、快速的任务：文件检索、简单文本提取、grep 查找、快速摘要、子代理的轻量查询。速度最快，token 最便宜。 | `Qwen/Qwen3.5-35B-A3B` |

## 附录

### 附录 A　常见问题与故障排查

| 现象 | 可能原因 | 处理方法 |
| --- | --- | --- |
| 命令行提示"不是内部或外部命令" | 环境变量未生效，或软件未安装成功 | 关闭命令行窗口重新打开；仍无效则重启电脑；最后检查安装是否成功 |
| `npm install` 报权限错误 | 未以管理员身份运行（Windows） | 右键选择"以管理员身份运行"，或在命令前加 `sudo`（Linux 与 macOS） |
| 安装过程长时间无响应 | 网络不通，或 npm 源访问缓慢 | 检查网络；可尝试更换为国内 npm 镜像源 |
| 提示 API Key 无效或认证失败 | 密钥复制不完整、带空格，或已过期被删除 | 重新复制密钥，注意去除首尾空格；必要时重新创建 |
| 提示余额不足 | 账户额度用尽或未充值 | 到对应平台充值，或改用有免费额度的平台 |
| 模型列表为空或看不到某模型 | 该平台未开通此模型，或模型 ID 填写错误 | 到平台模型广场核对模型 ID，注意大小写与斜杠 |
| 配置了路由但模型没变 | 未启用配置，或未重启智能体程序 | 在 CC Switch 中确认已启用，然后关闭并重新启动该产品 |
| 长任务进行到一半开始答非所问 | 上下文窗口溢出 | 拆分任务，或改用支持更长上下文的模型 |
| 输出质量忽高忽低 | 温度设置不合适 | 严谨任务调低温度，创意任务调高温度 |
| 智能体找不到本地文件 | 工作目录选择错误 | 确认启动时所在目录，或在提示词中给出完整路径 |
| 回答流畅但内容与事实不符 | 模型幻觉 | 见第 2 章。要求提供依据，关键信息交叉验证，降低温度，改用 RAG 接入真实资料 |
| 给出的参考文献查不到 | 幻觉中的文献编造 | 到 PubMed、Web of Science 或期刊官网按 DOI 与作者核对，确认前不得引用 |
| 问同一个问题两次答案不一样 | 采样随机性，或问题本身超出模型知识范围 | 降低温度；新开对话重问比对；必要时改用检索类方案 |
| 模型不知道最近发生的事 | 知识截止日期限制 | 开启联网搜索，或用 RAG 把最新资料接入 |
| 问私有资料时答不上来 | 模型训练时不可能见过这些资料 | 用 RAG 建立本地资料库，见第 3 章 |

> **提示**：排查问题有一个通用顺序：先确认网络，再确认密钥，最后确认配置项。绝大多数配置失败都出在这三处，而且按顺序排查能避免无谓的重装。

### 附录 B　术语表

| 术语 | 含义 |
| --- | --- |
| 大语言模型（LLM） | 通过大规模数据训练、能够理解与生成自然语言的基础模型，是智能体的智力来源 |
| 预训练 | 在海量文本上训练模型"预测下一个字"的阶段，模型由此获得语言能力与世界知识 |
| 监督微调（SFT） | 用人工编写的高质量问答对继续训练，让模型学会理解并按指令行事 |
| 偏好对齐 | 依据人类对答案的偏好打分来调优，使输出更安全、更有用，常见方法包括 RLHF 与 DPO |
| 参数 | 模型内部存储知识的可调节数值，参数量大体决定能力上限 |
| 知识截止日期 | 训练数据覆盖到的时间点，此后的信息模型并不掌握 |
| 幻觉（Hallucination） | 模型生成与事实不符但表述流畅、语气自信的内容 |
| 微调（Fine-tuning） | 用自己的数据继续训练模型，改变其风格或任务习惯，与 RAG 的外部检索相对 |
| 智能体（Agent） | 在大模型基础上增加规划、记忆与工具调用能力，可自主完成多步骤任务的系统 |
| SKILL | 封装了特定工作流程与工具用法的操作手册，可被智能体按需加载 |
| Tool（工具） | 完成单一动作的最小能力单元，如读取文件、执行搜索 |
| MCP | 模型上下文协议，规定智能体与外部工具、数据的统一接入方式 |
| 上下文（Context） | 模型在一次任务中能够同时"看到"的全部信息，包含历史对话与参考资料 |
| 上下文窗口 | 上下文的容量上限，超出后早期信息会被丢弃 |
| 温度（Temperature） | 控制生成随机性的参数，数值越低输出越确定，越高越发散 |
| 提示词（Prompt） | 用户输入给模型的任务指令 |
| Token | 模型处理文本的基本计量单位，也是计费单位，中文通常一个字约等于一个 Token |
| API Key | 调用模型服务的凭证，兼具身份识别与计费功能 |
| BaseURL | 接口地址，指明请求发往哪个服务端点 |
| 模型 ID | 模型在平台上的唯一标识，如 `deepseek-ai/DeepSeek-V4-Flash` |
| 路由 | 把原本指向某一模型的请求改道到另一模型的技术手段 |
| 沙箱 | 隔离的运行环境，在其中执行的操作不会影响本机系统 |
| Sub-agent（子代理） | 由主智能体派生、并行处理子任务的小规模智能体 |
| LSP | 语言服务器协议，为编辑器提供代码补全、跳转、诊断等能力 |
| RAG | 检索增强生成，先从资料库中检索相关内容，再连同问题交给模型作答的技术 |
| 向量库 | 存放文本向量的数据库，支持按语义相似度检索，是 RAG 的核心组件 |
| 切分（Chunking） | 把长文档切成若干语义完整片段的过程，切分质量直接决定 RAG 效果 |
| 重排序（Rerank） | 对粗召回的结果重新打分排序，提升检索精度的第二道工序 |
| Embedding | 把文本转换为向量的过程，是语义检索的基础 |
| 多模态 | 模型同时处理文字、图像、音频等多种输入形式的能力 |
| Hook | 在智能体执行流程的特定节点自动触发的自定义脚本 |
| LTS | 长期支持版，指软件中更新节奏慢、稳定性优先的版本分支 |
